# imapsync-web

Веб-панель для разовых миграций почты по IMAP. Движок переноса — imapsync,
вокруг него понятный интерфейс: импорт списка ящиков, проверка доступов
до старта, честные счётчики, живой лог, докачка после обрывов и отчёт о сверке.

> **Статус: задуманное сделано целиком, на живых почтовых серверах не обкатано.**
> Работает импорт списка, проверка доступов, инвентаризация, сопоставление папок,
> перенос через imapsync, прогресс, логи, докачка, «Досинхронить», сверка
> с приёмником и отчёт в xlsx, роли и журнал действий.
> Все принятые решения — в [DECISIONS.md](DECISIONS.md).

## Зачем, если есть imapsync

imapsync прекрасно переносит один ящик из командной строки. Проблемы начинаются,
когда ящиков двести:

- список приходит в Excel, в cp1251, с паролями, у половины из которых хвостовой пробел;
- какие-то ящики недоступны, и узнать об этом хочется **до** начала переезда, а не на третьи сутки;
- нужно видеть, что происходит прямо сейчас, а не смотреть в замерший терминал;
- обрыв связи не должен означать «начинай сначала»;
- перед переключением MX нужно догнать дельту, а после переключения — догнать ещё раз;
- заказчику нужен отчёт, что всё действительно доехало.

Этим и занимается панель. Сам перенос по-прежнему делает imapsync.

**Где мы не нужны:** у Google и Exchange Online есть свои миграторы, и они лучше.
Панель имеет смысл там, где штатного мигратора нет или он ничего не показывает:
on-prem Exchange, Zimbra, хостинг-панели, старые IMAP-серверы, сборная солянка.

## Что переносится, а что нет

Переносятся **письма и структура папок**.

**Не переносятся** — и это ограничение протокола IMAP, а не панели: календари,
контакты, задачи, заметки, правила обработки почты, автоответы, подписи, личная
адресная книга, категории Outlook, алиасы и пересылки. Их переносят отдельно
и другими средствами.

## Безопасность — прочитай до установки

Панель хранит **действующие пароли от почтовых ящиков** в расшифровываемом виде.
Иначе нельзя: IMAP требует пароль открытым текстом при логине.

- Пароли шифруются (Fernet), ключ берётся из переменной окружения и не лежит рядом с БД.
  Это защищает от кражи файла БД, но **не** от того, кто получил доступ к работающему
  приложению — оно обязано уметь расшифровать.
- **Не выставляй панель в интернет.** Локальная сеть, VPN или реверс-прокси
  с собственной аутентификацией.
- Пароли ящиков не показываются в интерфейсе никому, включая администратора.
- Креды не передаются imapsync через аргументы командной строки — иначе их
  видно любому пользователю хоста в выводе `ps`.
- Пароли автоматически стираются через 30 дней простоя проекта; есть кнопки
  «стереть креды» и «удалить проект». История, счётчики и отчёты остаются.

## Установка

Образ собирается GitHub Actions и лежит в ghcr.io — собирать ничего не нужно.

```bash
git clone https://github.com/Ttolyanich/imapsync-web.git
cd imapsync-web
cp .env.example .env
```

Заполни в `.env` как минимум `ADMIN_PASSWORD` и `FERNET_KEY`. Ключ шифрования:

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Если Python с пакетом `cryptography` под рукой нет — сгенерируй прямо в образе:

```bash
docker run --rm ghcr.io/ttolyanich/imapsync-web:latest python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Затем:

```bash
docker compose up -d
```

Панель поднимется на `http://127.0.0.1:8090`. Обновление — без пересборки:

```bash
docker compose pull && docker compose up -d
```

Собрать из исходников вместо готового образа можно, раскомментировав `build: .`
в `docker-compose.yml`.

### Где разворачивать

Скорость упирается в медленную сторону. Если панель стоит **в одной сети
с сервером-приёмником**, то через интернет идёт только чтение с источника,
а запись — по локалке; на больших ящиках это разница в сутки.

И учти: троттлинг почтовых сервисов срабатывает **на IP-адрес**. Если панель
работает из-за корпоративного NAT, слишком агрессивная параллельность может
временно отрезать от почтового сервиса весь офис, а не только миграцию.
Поэтому дефолты консервативные, а лимиты настраиваются на каждый сервер отдельно.

Рабочий ноутбук — плохая площадка: миграции идут ночами, а он уходит в сон.

## Пресеты серверов

Плитки выбора «откуда/куда» — это не украшение, а пресеты: они подставляют хост,
порт, режим аутентификации, словарь имён папок, безопасный лимит параллельности
и подсказки (например, что у Mail.ru нужен пароль приложения и включённый IMAP).

Пресеты лежат в [`presets/`](presets/) обычными YAML-файлами. **Добавить свой
почтовый сервис — это пул-реквест с одним файлом, без единой строчки Python.**
Пресеты, которые никто не проверял на живом сервере, помечены `verified: false`
и показываются в интерфейсе со значком.

Сейчас в комплекте: Mail.ru, Яндекс, Gmail, Exchange on-prem, Zimbra и
«Другой IMAP» с ручным вводом.

## Папки

Отдельная боль любой миграции — системные папки называются везде по-разному:
`Отправленные`, `Sent`, `Sent Items`, `[Gmail]/Sent Mail`. Наивный перенос
оставляет на приёмнике и то, и другое, с письмами вразнобой.

Панель определяет назначение папки сначала по тому, что объявил сам сервер
(SPECIAL-USE), и лишь потом по словарю имён; целевое имя берётся из пресета
приёмника. Получившаяся таблица соответствий **одна на весь проект** — её
показывают человеку, он правит и подтверждает один раз, дальше она применяется
ко всем ящикам.

## Отчёт о сверке

По кнопке «Сверить» панель заходит на приёмник и считает письма **там**, после
чего сравнивает с инвентаризацией источника, снятой до переноса. Это принципиально
не то же самое, что сложить собственные счётчики: они говорят, сколько писем мы
отправили, а не сколько долетело. Письмо могло быть отвергнуто сервером, не пройти
по размеру или попасть под политику хранения — увидеть это можно только опросив
приёмник.

Результат выгружается в xlsx: сводка, лист по ящикам с подсветкой недостачи
и лист расхождений по папкам.

## Разработка

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
flask --app app.wsgi run --debug
```

Для полного цикла нужен ещё `imapsync` в `PATH` (в Docker он ставится сам).

### Проверки

```bash
python tests/test_units.py
```

Классификация ответов почтовых серверов, опознание системных папок, загрузка
пресетов и — главное — правило «ошибку пароля не повторяем никогда». Последнее
не косметика: лишний повтор при массовой проверке блокирует доменные учётные
записи. Внешняя сеть не нужна.

```bash
SMOKE_PASSWORD=пароль_админа python tests/smoke_http.py
```

Сквозной сценарий по работающему на `:5010` экземпляру: вход, CSRF, создание
серверов из пресетов, мастер проекта, импорт «экселевского» CSV (cp1251,
разделитель `;`, хвостовой пробел в пароле, дубль, битый адрес) и очистка
паролей. Запускать по чистой базе.
